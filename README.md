# workflows

Reusable GitHub Actions workflows shared by the [@douglasjunior](https://github.com/douglasjunior) repositories.

## Commit authors

Checks the commits of a pull request or push:

- No commit may be authored, committed or co-authored by a known AI agent, or carry an agent signature in its message.
- On pull requests opened by the repository owner, every author and committer must be one of the owner's identities.

```yaml
name: Commit authors

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  commit-authors:
    name: Commit authors
    uses: douglasjunior/workflows/.github/workflows/commit-authors.yml@v1
```

The check reports as `Commit authors / Check commit authors`, which is the name to require in a ruleset.

`pull_request` checks every commit of a pull request, including the owner identity rule. `push` is limited to the default branch, where it checks what lands there, including pushes made through a ruleset bypass. Running `push` on every branch would report the same check twice on each pull request from a branch of the repository.

## Branch ruleset

Every repository protects its default branch and `feature/*` with one ruleset, kept in [`rulesets/protected-branches.json`](rulesets/protected-branches.json).

| Rule | Setting |
| --- | --- |
| Target | Default branch and `refs/heads/feature/*` |
| Restrict deletions | On |
| Block force pushes | On |
| Require a pull request | On, 0 approvals, squash merge only |
| Require status checks | `Commit authors / Check commit authors` plus the repository's own CI checks, without requiring the branch to be up to date |
| Bypass (always) | Repository admin role and the `douglasjunior-bot` GitHub App |

The required check names are the check run names shown on a pull request. A job of a reusable workflow reports as `<caller job name> / <job name>`, and a matrix job as `<job name> (<matrix value>)`. A required check that never runs keeps every pull request blocked, so add a check to the ruleset only after the workflow that reports it is on the default branch.

`douglasjunior-bot` is on the bypass list so release workflows can push the version commit to the default branch with an App token generated by [`actions/create-github-app-token`](https://github.com/actions/create-github-app-token). The `GITHUB_TOKEN` cannot bypass a ruleset in a personal account repository.

### Applying it to a repository

1. Install `douglasjunior-bot` on the repository. A ruleset can only list an App that is installed on the repository.
2. Add the repository's CI checks to `required_status_checks` in a copy of the JSON.
3. Create the ruleset:

   ```bash
   gh api -X POST repos/douglasjunior/<repo>/rulesets --input protected-branches.json
   ```

4. If a workflow pushes to a protected branch, set the `RELEASE_APP_ID` and `RELEASE_APP_PRIVATE_KEY` secrets.

## Versioning

Callers pin the major tag (`@v1`). Compatible changes move `v1`; breaking changes get a new major tag.
